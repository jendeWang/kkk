## 1. 部署前准备

### 1.1 发行方准备工作

在将部署包交付给学校之前，发行方需要：

1. **生成授权文件**（仅发行方操作）：

```bash
# 进入后端目录
cd backend

# 生成学校授权（6个月，最多100台设备）
python scripts/generate_license.py --school "某某职业技术学院" --months 6 --devices 100
```

生成后得到两个文件：
- `licenses/某某职业技术学院_20270108.policy` — 授权文件
- `licenses/某某职业技术学院_deploy_public.key` — 公钥文件

2. **交付给学校**：将上述两个文件发送给学校。

### 1.2 学校准备工作

1. 准备一台运行 Ubuntu 20.04 LTS 或 22.04 LTS 的服务器
2. 确保服务器可以访问互联网（用于安装依赖）
3. 准备服务器 IP 地址或域名
4. 获取发行方提供的授权文件

## 4. 一键安装（推荐）

### 4.1 上传部署包

使用 `scp` 或其他工具将 `deploy/` 目录上传到服务器：

```bash
# 示例：从本地上传到服务器
scp -r deploy/ root@your-server-ip:/opt/
```

### 4.2 运行安装脚本

```bash
# 登录服务器
ssh root@your-server-ip

# 进入部署目录
cd /opt/deploy

# 赋予脚本执行权限
chmod +x install.sh

# 运行一键安装
./install.sh
```

安装脚本会自动完成以下操作：
1. 更新系统软件包
2. 安装 Python 3、pip、Nginx
3. 创建安装目录 `/opt/iot-platform/`
4. 复制程序文件
5. 安装 Python 依赖
6. 配置 Nginx 反向代理
7. 创建 systemd 服务

### 4.3 配置授权文件

安装完成后，需要配置授权文件：

```bash
# 将发行方提供的授权文件复制到后端目录
cp /path/to/某某学校.policy /opt/iot-platform/backend/.policy
cp /path/to/某某学校_deploy_public.key /opt/iot-platform/backend/.auth
```

### 4.4 启动服务

```bash
# 启动后端服务
systemctl start iot-platform

# 设置开机自启
systemctl enable iot-platform

# 查看服务状态
systemctl status iot-platform
```

### 4.5 验证安装

打开浏览器访问：`http://your-server-ip`

应该能看到登录页面，使用默认账号登录：
- 用户名：`admin`
- 密码：`admin123`

## 5. 手动安装（高级用户）

### 5.1 更新系统

```bash
apt-get update
apt-get upgrade -y
```

### 5.2 安装依赖

```bash
# 安装基础依赖
apt-get install -y python3 python3-pip nginx

# 安装可选依赖（用于硬件特征采集）
apt-get install -y blkid
```

### 5.3 创建安装目录

```bash
mkdir -p /opt/iot-platform/{backend,frontend}
```

### 5.4 复制程序文件

```bash
# 复制后端
cp -r /path/to/deploy/backend/* /opt/iot-platform/backend/

# 复制前端
cp -r /path/to/deploy/frontend/* /opt/iot-platform/frontend/
```

### 5.5 安装 Python 依赖

```bash
cd /opt/iot-platform/backend
pip3 install -r requirements.txt
```

### 5.6 配置授权文件

```bash
# 将发行方提供的授权文件复制到后端目录
cp /path/to/某某学校.policy /opt/iot-platform/backend/.policy
cp /path/to/某某学校_deploy_public.key /opt/iot-platform/backend/.auth
```

### 5.7 启动后端

**方式一：直接运行（调试用）**

```bash
cd /opt/iot-platform/backend
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

**方式二：使用 systemd（生产环境）**

创建服务文件：

```bash
cat > /etc/systemd/system/iot-platform.service << 'EOF'
[Unit]
Description=IoT Platform Backend
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/iot-platform/backend
ExecStart=/usr/bin/python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```

启动服务：

```bash
systemctl daemon-reload
systemctl enable iot-platform
systemctl start iot-platform
```

## 6. 授权文件配置

### 6.1 授权文件说明

平台采用离线授权机制，无需联网验证：

- **`.policy` 文件**：包含学校名称、过期时间、设备上限等信息，由发行方私钥签名
- **`.auth` 文件**：公钥文件，用于验证授权文件的签名

### 6.2 部署授权文件

将发行方提供的两个文件放到 `backend/` 目录并重命名：

```bash
# 假设收到的文件是：某某职业技术学院_20270108.policy 和 某某职业技术学院_deploy_public.key

# 复制并重命名
cp 某某职业技术学院_20270108.policy /opt/iot-platform/backend/.policy
cp 某某职业技术学院_deploy_public.key /opt/iot-platform/backend/.auth
```

### 6.3 授权状态说明

| 状态 | 表现 | 处理建议 |
|------|------|---------|
| ✅ 授权有效 | 所有功能正常使用 | 无需处理 |
| ⚠️ 授权过期（只读） | 可查看数据，不可新增设备或下发命令 | 联系发行方续期 |
| ❌ 授权失效 | 系统拒绝启动 | 检查授权文件是否正确，联系发行方 |

### 6.4 续期流程

1. 学校联系发行方申请续期
2. 发行方重新生成授权文件
3. 学校替换 `.policy` 文件
4. 重启后端服务

## 8. Nginx 配置

### 8.1 配置反向代理

安装脚本已自动配置 Nginx，如果需要手动配置：

```bash
# 复制配置文件
cp /opt/iot-platform/frontend/nginx.conf /etc/nginx/sites-available/iot-platform

# 创建符号链接
ln -sf /etc/nginx/sites-available/iot-platform /etc/nginx/sites-enabled/

# 测试配置
nginx -t

# 重启 Nginx
systemctl reload nginx
```

### 8.2 修改域名

编辑 `/etc/nginx/sites-available/iot-platform`，修改 `server_name`：

```nginx
server {
    listen 80;
    server_name your-domain.com;  # 修改为实际域名
    
    # 前端静态文件
    location / {
        root /opt/iot-platform/frontend/dist;
        try_files $uri $uri/ /index.html;
        index index.html;
    }
    
    # 后端 API
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    
    # WebSocket/SSE 支持
    location /api/v1/sse/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_buffering off;
        proxy_cache off;
    }
}
```

## 9. SSL 证书配置（可选）

### 9.1 使用 Let's Encrypt

```bash
# 安装 Certbot
apt-get install -y certbot python3-certbot-nginx

# 获取证书
certbot --nginx -d your-domain.com

# 自动续期
certbot renew --dry-run
```

### 9.2 使用自签名证书（测试用）

```bash
# 生成自签名证书
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/ssl/private/iot-platform.key \
    -out /etc/ssl/certs/iot-platform.crt
```

修改 Nginx 配置支持 HTTPS：

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;
    
    ssl_certificate /etc/ssl/certs/iot-platform.crt;
    ssl_certificate_key /etc/ssl/private/iot-platform.key;
    
    # 其他配置...
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}
```

## 10. 模拟器测试

系统内置设备模拟器，可自动生成传感器数据用于测试。

### 10.1 模拟器功能说明

| 功能 | 说明 |
|------|------|
| 自动启动 | 后端服务启动时自动运行模拟器 |
| 数据生成 | 每3秒为所有在线设备生成9项传感器数据 |
| 支持传感器 | 温度、湿度、光照、土壤湿度、CO₂、土壤温度、土壤pH、风速、雨量 |
| 告警联动 | 自动触发告警规则和场景联动 |
| SSE推送 | 实时推送数据到前端 |

### 10.2 测试步骤

#### 步骤1：确保服务已启动

```bash
# 查看服务状态
systemctl status iot-platform

# 如果未启动，启动服务
systemctl start iot-platform
```

#### 步骤2：查看模拟器日志

```bash
# 查看后端日志，确认模拟器已启动
journalctl -u iot-platform -f

# 应该看到类似日志：
# Device simulator started
# MQTT service started
```

#### 步骤3：查看设备列表

```bash
# 使用 curl 测试 API
curl http://localhost:8000/api/v1/devices/

# 应该返回设备列表，包含默认创建的大棚设备
```

#### 步骤4：查看实时数据

```bash
# 获取设备实时遥测数据
curl "http://localhost:8000/api/v1/devices/1/telemetry/latest"

# 应该返回温度、湿度等传感器数据
```

#### 步骤5：通过前端测试

1. 打开浏览器访问 `http://your-server-ip`
2. 使用账号 `admin/admin123` 登录
3. 进入**仪表盘**页面，查看环境实时监测数据
4. 进入**数字孪生**页面，查看3D大棚和传感器数据
5. 进入**数据大屏**页面，查看全屏数据展示

#### 步骤6：测试执行器控制

1. 进入**仪表盘**页面
2. 在**执行器控制**区域，点击设备开关（通风扇、补光灯、灌溉水泵）
3. 确认设备状态变化
4. 查看传感器数据是否受执行器影响：
   - 开启通风扇 → 温度下降、CO₂下降
   - 开启灌溉水泵 → 湿度上升、土壤湿度上升
   - 开启补光灯 → 光照强度上升

#### 步骤7：测试定时任务

1. 进入**执行器控制**页面（左侧菜单）
2. 切换到**定时任务**标签
3. 点击**新建任务**按钮
4. 配置定时任务：
   - 任务名称：例如"定时通风"
   - 选择设备
   - 选择执行器（如通风扇）
   - 设置目标值（true/false）
   - 设置Cron表达式（如 `0 9 * * *` 每天9点）
5. 保存任务并启用

## 11. 常见问题

### 11.1 服务启动失败

**问题**：`systemctl status iot-platform` 显示失败

**排查步骤**：

```bash
# 查看详细日志
journalctl -u iot-platform --no-pager

# 常见错误：
# 1. 授权文件缺失或无效
#    确保 .policy 和 .auth 文件存在且内容正确
# 2. 端口被占用
#    lsof -i :8000
# 3. 依赖缺失
#    cd /opt/iot-platform/backend && pip3 install -r requirements.txt
```

### 11.2 前端无法访问

**问题**：浏览器访问显示 404

**排查步骤**：

```bash
# 检查 Nginx 状态
systemctl status nginx

# 检查前端文件是否存在
ls -la /opt/iot-platform/frontend/dist/

# 检查 Nginx 配置
nginx -t
```

### 11.3 API 请求失败

**问题**：前端显示"请求失败"或 500 错误

**排查步骤**：

```bash
# 检查后端服务状态
systemctl status iot-platform

# 检查后端日志
journalctl -u iot-platform -f

# 直接测试 API
curl http://localhost:8000/api/v1/devices/
```

### 11.4 授权过期

**问题**：页面提示"授权已过期，当前仅支持只读访问"

**解决方案**：联系发行方续期，替换新的 `.policy` 文件后重启服务。

### 11.5 迁移到新服务器

**问题**：将系统迁移到新服务器后授权失效

**说明**：授权绑定服务器硬件特征，签发 30 天内允许迁移，超过 30 天需联系发行方重新申请授权。

### 11.6 模拟器无数据

**问题**：前端显示"--"或无数据

**排查步骤**：

```bash
# 检查服务是否启动
systemctl status iot-platform

# 检查日志中是否有模拟器相关信息
journalctl -u iot-platform --no-pager | grep -i simulator

# 检查是否有在线设备
curl http://localhost:8000/api/v1/devices/?status=online

# 手动触发一次数据刷新
curl -X POST http://localhost:8000/api/v1/devices/1/shadow/sync
```

## 12. 升级指南

### 12.1 备份数据

```bash
# 备份数据库
cp /opt/iot-platform/backend/iot_platform.db /opt/iot-platform/backend/iot_platform.db.backup

# 备份授权文件
cp /opt/iot-platform/backend/.policy /opt/iot-platform/backend/.policy.backup
cp /opt/iot-platform/backend/.auth /opt/iot-platform/backend/.auth.backup
```

### 12.2 停止服务

```bash
systemctl stop iot-platform
systemctl stop nginx
```

### 12.3 替换程序文件

```bash
# 复制新的后端文件
cp -r /path/to/new/deploy/backend/* /opt/iot-platform/backend/

# 复制新的前端文件
cp -r /path/to/new/deploy/frontend/dist/* /opt/iot-platform/frontend/dist/
```

### 12.4 恢复授权文件

```bash
# 恢复授权文件（升级时不要覆盖）
cp /opt/iot-platform/backend/.policy.backup /opt/iot-platform/backend/.policy
cp /opt/iot-platform/backend/.auth.backup /opt/iot-platform/backend/.auth
```

### 12.5 重启服务

```bash
systemctl start iot-platform
systemctl start nginx
```
