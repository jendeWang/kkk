### 1.2 各层详细说明

#### 感知层（Perception Layer）
- **ESP32节点**：每节点可接入8-16路传感器和4-8路执行器
- **传感器网络**：温湿度、光照、CO₂、土壤湿度、土壤pH、风速风向、雨量、水体EC值
- **执行器网络**：卷帘电机、通风扇、滴灌电磁阀、补光灯、加热膜、雾化器、遮阳网电机
- **通信协议**：MQTT over WiFi
- **供电方式**：DC 12V总线供电，节点内置降压到5V/3.3V

#### 边缘层（Edge Layer - RK3588）
- **数据采集服务**：周期性轮询ESP32节点，数据本地持久化
- **本地规则引擎**：支持IF-THEN规则、阈值告警、联动控制（断网时本地自治）
- **视频处理服务**：接入USB/RTSP摄像头，本地运行YOLOv8进行病虫害识别
- **MQTT桥接**：本地Broker ↔ 云端Broker，支持断线缓存
- **本地HMI**：触摸屏界面，现场调试与控制
- **OTA升级管理**：ESP32固件和边缘网关自身的远程升级

#### 云层（Cloud Layer）
- **EMQX Broker**：MQTT 5.0协议，支持共享订阅、遗嘱消息
- **FastAPI服务**：用户认证、设备管理、数据查询、告警管理、AI分析、知识图谱查询
- **PostgreSQL + TimescaleDB**：关系数据 + 时序数据混合存储
- **Redis**：实时数据缓存、会话管理、消息队列
- **Neo4j**：病虫害知识图谱、作物生长知识图谱
- **YOLOv8推理服务**：基于FastAPI封装，GPU加速

#### 应用层（Application Layer）
- **Web管理端**：设备管理、数据监控、规则配置、用户管理
- **数据大屏**：Three.js三维大棚可视化、实时数据看板
- **移动端**：响应式H5，支持手机查看数据、接收告警

## 三、技术难点及解决方案

### 难点1：ESP32节点低功耗与实时性平衡

**问题**：高频采集 vs 低功耗 vs 实时响应，三者难平衡

**解决方案**：
- 采用"轻度休眠 + 事件唤醒"策略
- 正常工作时CPU 80MHz（非240MHz），降低功耗
- 采集间隙进入Light Sleep模式
- MQTT保持连接，5秒KeepAlive
- FreeRTOS任务优先级：控制任务 > 通信任务 > 采集任务

### 难点2：大规模时序数据存储与查询性能

**问题**：50+传感器，每5秒一次，每天86万条，一年3亿条

**解决方案**：
- 采用 PostgreSQL + TimescaleDB 时序扩展
- 超表按天自动分区
- 连续聚合预计算小时/天的聚合数据
- 7天前数据自动压缩（压缩比约10:1）
- 原始数据保留3个月，聚合数据保留1年

### 难点3：MQTT消息可靠性与设备状态管理

**问题**：设备随时可能离线，如何准确感知和保证命令不丢失？

**解决方案**：
1. **设备状态管理**：
   - MQTT遗嘱消息（LWT）：异常离线自动发布
   - 心跳机制：30秒一次，60秒未收到判定离线
   - 保留消息（Retained）：新订阅立即获最新状态
2. **命令可靠性**：
   - 控制命令QoS=1，确保至少到达一次
   - 命令带唯一ID，设备回复ACK，服务端去重
   - 超时重传：5秒未ACK重发，最多3次
3. **设备影子（Device Shadow）**：
   - 保存期望状态（desired）和上报状态（reported）
   - 设备上线自动同步影子，执行差异部分

### 难点4：YOLOv8在RK3588上的部署与性能

**问题**：CPU推理慢（<5FPS），如何充分利用NPU？

**解决方案**：
1. **模型转换与量化**：
   - PyTorch → ONNX → RKNN格式转换
   - INT8量化：500张校准数据集
   - 量化后模型减小75%，速度提升3-4倍，精度损失<2%
2. **推理优化**：
   - RKNN-Toolkit2工具链，针对NPU优化算子
   - 输入分辨率：640→416（速度提升2倍）
   - 多线程预处理：OpenCV多线程解码
3. **性能目标**：
   - YOLOv8s（INT8，416x416）：NPU推理约30FPS

### 难点5：Three.js三维大棚与实时数据映射

**问题**：3D渲染流畅性 vs 数据实时更新

**解决方案**：
1. **3D建模与优化**：
   - Blender建模，导出glTF 2.0格式
   - 模型减面：控制在1万三角形以内
   - 纹理压缩：KTX2格式，减少显存占用
2. **Three.js渲染优化**：
   - InstancedMesh渲染重复物体
   - 材质共享，减少Draw Call
3. **数据映射方案**：
   - WebSocket实时推送（1秒/次）
   - Pinia数据缓存，避免重复请求
   - 温湿度：颜色渐变（蓝→绿→红）
   - 设备状态：颜色+简单动画（风扇转动、卷帘移动）

### 难点6：边缘规则引擎可视化配置与高效执行

**问题**：可视化配置 vs 高效执行 vs 云边同步

**解决方案**：
1. **规则模型**：触发条件 → 条件判断 → 执行动作（三段式）
2. **可视化编辑器**：基于Vue Flow拖拽式节点编辑
3. **规则执行**：事件驱动，单条规则判断<1ms
4. **云边同步**：MQTT同步规则，版本管理，增量更新

### 难点7：系统整体安全性设计

**问题**：物联网设备控制涉及物理安全

**解决方案**：
1. **设备安全**：一机一密、固件签名、禁用调试接口
2. **网络安全**：MQTT over TLS、防火墙、API网关限流
3. **应用安全**：JWT认证+刷新令牌、RBAC权限、操作日志审计
4. **数据安全**：敏感数据加密、每日备份、HTTPS传输

### 难点8：多设备OTA升级可靠性

**问题**：升级变砖怎么办？如何批量管理？

**解决方案**：
1. **ESP32 OTA**：双分区设计，失败自动回滚
2. **网关OTA**：A/B分区系统，原子升级
3. **版本管理**：版本库、灰度发布、定时升级
4. **安全措施**：RSA签名验证、升级失败自动重试
